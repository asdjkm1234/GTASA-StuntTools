# 06·2·01 — Traffic simulation core (agents, rings, routes)

[← chain](../readme.md) · needs: 1/02 (directed lanes), 1/03 (densities) · next: [02 driver AI](02-driver-ai.md)

One simulation, three fidelity rings, agent identity preserved throughout. This plan is ALSO the
simulation SPEC (decision D5): the C++ twin in 2/05 implements this file, and the shared fixtures are
written here first.

## Agent model (non-negotiable)

- SoA typed arrays per ring: `routeId, segmentIndex, s, speed, seed, kindId, laneIndex, state`. Zero
  per-agent allocation at steady state (the soak lane will check `heapFlat`).
- Identity: agent = `(seed, route)`; LOOK (model via cargrp weights, colour via carcols) and BEHAVIOUR
  profile (aggressiveness, target speed factor) derive deterministically from `seed`. A
  demoted-then-promoted agent re-materializes identically.
- Routes: seeded walk over the DIRECTED lane graph with purpose weights (through-traffic prefers big
  roads; local seeds putter), regenerable from `(seed, entryNode, timeOfDay)`. Authored routes from the
  sidecar override. Route keys are `(area, nodeId)` — identical in both hosts.
- Determinism: same seed + same clock → same city, in the engine, in the ASI, and in tests. No
  `Math.random`, no wall clock — the game clock only.

## The rings (engine truths baked in)

- **Ring 2 FLOW** (0.5–2.4 km, under the fog cull): `s += v·dt`; junction choice = seeded hash;
  car-following = per-lane clamp against the leader (one sorted pass per busy segment); lights beyond
  ring 1 collapse to a stochastic slow factor at controlled nodes. Output: position/heading/kind buffer
  for 2/04's corona streams. Bench: 5,000 agents ≤ 1 ms.
- **Ring 1 KINEMATIC** (~150–500 m): curve-smoothed following (sidecar beziers where authored, arc
  blending where not), lane changes, full light/stop compliance, gap acceptance at junctions. NO
  physics body, NO collider, NO collision casts — ground height comes from graph Z + link gradient
  (1/02), smoothed; the world under a ring-1 car may not even be streamed (streaming follows the
  player — a restriction, not a choice).
- **Ring 0 FULL** (≤ ~150 m, the collision radius): hands the agent to the gameplay layer — a real
  spawned vehicle (existing `spawnVehicle` path) with the 2/02 driver following the same route.
  Ring-0 NPC count is a hard budget from the measured physics slice (~8 µs/car/step; start ~24 NPCs
  ≈ 0.2 ms/step + headroom for parked/player).
- **Promotion/demotion**:
  - ring 1→0 is PREDICTIVE: promote by time-to-contact (closing speed), not distance, so a car closing
    at 30 m/s is a real body long before touch range; frustum bias (behind-camera agents promote later);
    budget: ≤ 1 materialization/frame (the spawn tail is 0.2–0.3 ms — measured, plan 091).
  - Hysteresis on every ring boundary (the threshold-decision restriction: continuous signal or clocked
    hysteresis, never a raw threshold).
  - Demotion serializes back to the array row; the vehicle entity despawns through the existing
    VehicleLodSystem discipline (placement-anchored, the 059 lesson).
  - If ring 0 is full, the nearest ring-1 agent STAYS kinematic and visible — never a despawn pop; the
    sim slows promotion pressure by routing agents around the player's cell (an AAA norm).
- **Ring 2→1 materialization** uses the far-rendering path (2/04), not entities.

## Population control

Alive-seed counts per zone × hour from `DensityField` (1/03) with a smooth cross-fade on hour changes
(popcycle semantics: day/night character shift). The global caps are OURS (engine budgets), not SA's
pool sizes — legacy limits are not our limits; the SA host applies its own caps in 2/05.

## Scheduling

Main-thread tick first (it is array math; the 2 ms gate is the design constraint), measured per ring in
the debug overlay from day one. A worker move is a recorded deferred optimization with its price
(marshalling, the frameSpans between-frame rule) — not built until a measurement says so.

## Fixtures (the parity contract with 2/05)

- `traffic-fixtures/`: (graph slice, sidecar, seed, clock window) → per-tick positions/states golden
  files, generated by THIS implementation once accepted, consumed by the C++ twin's unit-parity tests.
- Fixture slices: one LS grid junction, one country highway, one light-controlled crossing, one lane
  merge.

## Goals gate

1. *Authored data:* densities (popcycle), car mixes (cargrp), lanes/directions (navi), speeds — all
   authored, all obeyed.
2. *Original:* SA simulates a ~100 m bubble with despawn-on-look-away; identity-preserving rings are
   our answer — no spawn-despawn soup.
3. *Better:* demonstrated by the 5/01 acceptance program (fullness metrics + field verdict) and the
   bench gates here.
4. *Cost:* sim tick ≤ 2 ms full rings; promotion ≤ 1 spawn/frame; zero casts; zero steady-state GC.
5. *Contract:* no new file names (sidecar owns those); config keys under `config.traffic.*` documented
   in `docs/commands.md`.
